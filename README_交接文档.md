# 央行货币政策跟踪看板 — 项目交接文档

> 写给接续开发的 agent：本文档包含项目全貌、运行方式、架构设计、五轮用户审核演化出的全部规则、以及踩过的坑。读完本文档 + `extractor.py` 内的注释，即可直接接续工作。
> 文档日期：2026-07-23

---

## 1. 项目是什么

从**金融时报 / 中国金融新闻网**两位记者（**马梅若、马玲**）的署名文章中，自动摘取央行货币政策相关表态，组织成**五维度看板**：

| 维度 | 条数 | 内容 |
|---|---|---|
| 经济形势 | 176 | 央行/专家对"经济怎么样了"的判断（量、价、结构、趋势、外部环境） |
| 货币政策取向 | 181 | 货币政策立场表态（适度宽松、支持性、观察期、按兵不动、信号释放） |
| 国债买卖 | 30 | 央行公开市场国债买卖操作本身（开展/暂停/恢复/净买入卖出） |
| 资金利率态度 | 39 | 有明确含义的资金面信息（DR001/DR007 数值、与政策利率位置关系、松紧判断） |
| 债券市场态度 | 39 | 对债市收益率/长端利率/利率风险的态度 |

**当前状态**：379 篇保留文章、465 条定稿摘句，已经过**五轮用户逐条审核**。看板为最终成品，含审核工具（可继续标记）。

## 3. 快速开始

环境：Python 3.12，依赖 `requests beautifulsoup4 openpyxl`。

```bash
# 1) 修改各脚本顶部的绝对路径常量（CACHE/REPORT/OUT/MARKS、sys.path），
#    当前指向 /mnt/agents/work/央行货币政策看板_融合版/，按新环境改

# 2) 重新生成看板（数据完整时无需重跑爬虫）
python3 code/gen_audit.py    # 审核看板 → data 同级 output/dim_audit.html
python3 code/gen_final.py    # 最终看板 → output/final_dashboard.html
python3 code/gen_xlsx.py     # xlsx 明细

# 3) 全量重跑（含爬虫，慎用——会用新数据覆盖缓存）
python3 code/run_full.py
```

**重要**：`gen_audit.py` 和 `gen_final.py` 的数据逻辑必须保持一致（提取→并轨→删除清单→改归→去重）。改规则只改 `extractor.py`；改清单应用逻辑要同步改两个生成器（当前是代码复制，未抽公共模块——可重构）。

## 4. 架构与数据流

```
马梅若马玲_文章正文全量.csv（原始数据源，未附，可用 crawler 重建）
    → merge_csv.py → articles_cache.json（文章全文缓存）
    → run_full.py  → pipeline_report.json（kept 379篇 / removed，含标签+dims计数）
    → gen_audit.py / gen_final.py：
        对 kept 每篇调用 extractor.extract_core_view() 重新提取
        → 工作重点并轨（reassign_work_focus）
        → 应用用户删除清单（user_marks_r3/r4.txt）
        → 资金句改归 + 文章内跨维度去重
        → 渲染 HTML
```

### extractor.py 提取链路（核心）

1. **classify_article**：按标题关键词打标签（流动性投放/利率政策/货币政策例会/国债买卖/金融统计数据/宏观点评/货币政策·宏观调控）
2. **should_include / is_skip_article**：文章级排除（托管余额、一图看懂、法律修订、团拜会等）
3. **句子级前置过滤**：extract_core_view 内循环开头的 `continue` 规则（美国孤立句、财政取向、宏观审慎、家电、地缘政治等——注意：前置过滤影响所有维度，勿轻易加词）
4. **七策略引语提取**：策略0行长兜底 / 策略1直接引语 / 策略2引号在前 / 策略3专家 / 策略4总结词 / 策略5政策叙述 / 策略6经济描述 + 策略QA答记者问 + 策略M误区合并（"一是/二是认为……"误区句与"实际上……"澄清句合并）
5. **split_eco_from_policy**：混合句拆分（经济现状归经济形势，政策应对归取向）
6. **classify_dimension**：打分+否决制多标签分类（一句可进多维度）→ max_per_dim=3 每文每维度截断
7. **文章内跨维度去重**：资金态度让位（return 前）
8. **is_fund_meaningful**：资金态度门槛（见 §6 第四/五轮规则）

### 审核交互（用户工作流）

用户在 dim_audit.html 逐条点「对/不对」（localStorage 键 `dim_audit_marks_v3`）→「导出不对清单」贴回 → 助手把清单存为 `user_marks_rN.txt` 并**同时**做两件事：①清单落盘精确删除 ②把删除句的共性**规则化**进 extractor.py 防复发。这是本项目的核心迭代模式，请延续。

## 5. 用户偏好画像（最重要，五轮审核沉淀）

用户要的是**"央行态度"而不是"新闻叙述"**：

- **取向型 > 叙述型**：要立场/表态/信号/机制/政策含义；不要操作量、纯事实罗列、事件经过
- **删除偏好**：毫不相干案例、话题边缘（单独消费/单独财政/融资平台化债）、纯事实（降准xx/降息xx）、结构性（政策转型/五篇大文章/结构性工具）、政治意味大（习近平新时代/党中央国务院决策部署/金融强国/政治站位）、务虚表态
- **资金利率态度只要"明确含义"**：DR001/DR007 具体数值与变动、与政策利率的位置关系（围绕/偏离/上破/下破）、明确松紧判断。**不要**：加量缩量续作、净投放净回笼xx亿、到期量、MLF中标利率、操作量为零、纯市场状态罗列（"年初以来货币市场保持宽松……均值x%"）、操作归因尾巴（"……适度调减等影响下，市场利率回升"）、适度宽松类取向表述、企业案例
- **跨维度**：同一句已摘入其它维度的，不再重复摘入资金利率态度（资金态度优先级最低）
- **直接谈资金利率/资金面/DR001 的句归资金利率态度**，不进货币政策取向——**例外**："协调配合/流动性安排"句归货币政策取向（用户第二轮明确要求）
- **维度归类细则**：特别国债发行+流动性安排+协调配合 → 货币政策取向（不是债市）；商业银行购债 ≠ 央行国债买卖；LPR 归因段（出口偏强/投资回升）→ 经济形势，"必要性迫切性不高/观察期" → 货币政策取向

## 7. 血泪教训（勿回退这些修复）

1. **/tmp 会被沙箱清空**（本项目因此丢过两轮修改）——所有工作必须在持久目录，勤同步。
2. **策略守卫原则**：每个提取策略必须带 `if not quotes_from_this:` 守卫，先命中策略独占该句。策略1曾漏守卫导致"二是认为……"裸误区句重复抓出。
3. **fallback 泄漏陷阱**：`classify_dimension` 末尾 `if not dims: fallback = defaults[tag]`——被 veto 的句、被资金门槛拦的句会因 dims 变空而**转吃其它维度的默认通道**（利率政策→取向、宏观点评→经济形势、国债买卖→债市）。修复：`raw_fund_hit and not has_fund → fallback=[]`，以及 has_eco_veto/has_policy_veto 剔除对应默认维度。**改分类逻辑后必须回归验证四维度条目零变动**（用旧看板 HTML 解析做基线对比）。
4. **多处 strip 引号**：537行和643行两处 `.strip('"""“”…')` 都会制造孤立闭引号（「"收短"源于……」→「收短”源于……」），两处都打了补丁（`^[^“”"]{1,12}[”"][^“”]` → 补回 `“`）。新增 strip 点时记得同步。
5. **max_per_dim=3 容量挤压**：新合格句会挤掉同维度后来的句——旧句"消失"先看是不是被挤的，别当 bug 修。
6. **爬虫 3000 字截断**：`len(content)==3000` 即截断标志。39 篇保留文章被截，2026-07-23 已重抓补全 19 篇（重抓条件 `len(text)>3000` 才覆盖）；其余 20 篇重抓反而更短（页面结构变化），保留原 3000 字版。
7. **删除匹配要宽松**：用户导出的清单句与看板句有空格/省略号截断差异，匹配用 `_norm()`（去空白）+ 双向包含。
8. **审核看板 localStorage 键**已升到 `dim_audit_marks_v3`；若看板条目结构大变请继续升键（v4），避免旧标记错位。

## 8. 已知待办 / 后续方向

- 资金利率态度 39 条用户可能还会再筛一轮（延续"清单+规则化"模式即可）
- 20 篇文章仍是 3000 字截断版（见 §7.6），如原文页面恢复可再补
- `gen_audit.py` 与 `gen_final.py` 数据收集逻辑重复，建议抽公共模块（如 `pipeline.py`）防止两边漂移
- xlsx 的 dims 计数是 extract 原始计数（未含并轨/删除清单），与看板条数口径不同——如需一致要在 gen_xlsx 前重算（当前做法：重算 pipeline_report 的 dims 后再跑 gen_xlsx）
